| **A failed review is stored as the document's latest review** | Medium (new 2026-10-28) | Found by the memory audit ([context_and_memory_audit.md](context_and_memory_audit.md) §6), read from the code, not reproduced. When the review's model call fails, `llm_caller` leaves `llm_response = "Error: LLM call failed — …"`, and `memory_writer` saves any non-empty `llm_response` on a `contract_review` turn — so `save_review` stores the error string as a review. `load_latest_review` then returns it, and every later chat turn on that document injects it as the PRIOR REVIEW ("answer recall questions from this review") in place of the last good one. | **The reranker has never run** | **High** | Found during the trace-coverage audit (2026-09-16) and confirmed on a live turn the same day. `.env` carries `RERANKER_ENABLED=true` with `RERANKER_URL=` **empty**. `rerank()` guards on `reranker_enabled` and on empty `results`, but **not on an empty URL** ([rag/reranker.py:74-80](../rag/reranker.py)), so every call falls through to `_call_rerank` → `httpx.post("")` → `httpx.UnsupportedProtocol: Request URL is missing an 'http://' or 'https://' protocol.` — swallowed by the bare `except Exception` at [rag/reranker.py:119](../rag/reranker.py), one `logger.warning`, `return results[:n]`. **Config says the reranker is on; it has never run, and every local RAG answer has been unreranked.** Live evidence from a baseline research turn on 2026-09-16: three `WARNING rag.reranker: Reranker error: Request URL is missing an 'http://' or 'https://' protocol. — using original ranking` lines in the backend log, and the matching ERROR `POST` CLIENT spans to `http.url: "/"` in the trace (httpx instrumentation making it visible for the first time). `.env.remote.example` sets no reranker keys either, so the VM inherits the same defaults — though the VM's live `.env` was **not** inspected, so nothing stronger is claimed about production. **This is itself a textbook class-3 silent degradation — the argument for the whole trace-coverage feature in miniature**: a quality loss with a real cause, a real log line, and no signal anywhere an attorney or an analyst would look. | **Raising the MSA cap requires solving "the MSA must not absorb history" first** | Medium | Attempted 2026-08-27 on `feat/compaction-decision-log`, **reverted** (`2e12745`, `94472ff`) — recorded here because the failure is the interesting part and the next attempt will hit it again. The change was: make `msa_max_chars` a ceiling rather than a size (24 000 → 100 000, so the full 73 152-char MSA is sent), bound it per path by subtraction (`review_headroom_chars − document − playbook`), and have `_cap_chat_context` trim the MSA before the document. All of that is defensible in isolation. **It broke compaction.** The attach-time bound knows the document and the playbook but NOT the history, so the MSA claims every remaining character and the assembly pins itself to the budget. Measured live on two consecutive turns of the same document: turn 1 `16 008 + 30 412 + MSA 36 259 + history 0 + 7 208 = 89 887`; turn 2 `16 008 + 30 412 + MSA 27 712 + history 8 541 + 7 214 = 89 887`. Identical totals — the MSA shrank by exactly the history that appeared. Consequences: `pct` is pinned at 99 and can never fall, so `can_compact` is permanently true; anything a compaction frees the MSA immediately re-claims, so auto fires every ~2 turns forever and never relieves anything. That is precisely the churn loop `compaction_auto_min_chars` exists to prevent, reintroduced through a different door — and it silently invalidates the guard the floor relies on ("a successful compaction drops `pct` back under the warn line"). A second defect in the same attempt: the "spend the MSA only if it saves the document" rule means that at large history the MSA is kept WHOLE while the contract is cut and the prompt is *still* over budget — the worst of the three outcomes, and the opposite of the principle it was written under. That rule was contorted to satisfy a pathological existing test (budget 2 000, MSA 8 chars) instead of updating the test. **What the next attempt needs:** the MSA's bound must be computed from what is left AFTER history and the review block, not before them — which means it cannot be decided at attach time in `_build_chat_grounding`, where neither is known. Either move the decision to the assembly point in `_run_doc_chat`, or give the MSA a share of the budget rather than the remainder so `pct` still moves with history. Worth doing: the 24 000 cap really does answer MSA-conflict questions from 33% of the MSA, and `feat/context-budget` really did leave 4x headroom unused. But it is a design task, not a constant change. See also the corpus-overfitting row: 24 000 is itself a corpus-derived number, measured against a window we no longer run. |
| **Every measured constant here is a property of a FOUR-document corpus** | **High** | Raised 2026-08-27, and the more general form of the bug fixed the same day: `compaction_auto_min_chars` was 20,000 because that was a plausible number *on one afternoon's conversation*, and it turned out to be unreachable by construction. The corpus is the same kind of environment. Everything below was measured against the Trinetix MSA, its model SOW, an NDA and a BAA — four documents, one language, one drafting house, all clean digital text. **Classify before trusting any of them.** *Mechanism-derived (safe at scale, because they describe a format or a protocol):* `compaction_auto_min_chars=4000` (segment overhead), `compaction_keep_recent_messages=2`, `compaction_min_quotes`/`max_quotes`, `ollama_num_ctx` (a coupling to the server, not a choice), the review-path headroom in `llm_caller.py` (derived from `ollama_num_ctx` and `ollama_num_predict_review`), `db_pool_timeout`. *Corpus-derived (will go stale, in rough order of blast radius):* **`min_confidence_score=0.45` plus `retrieval_top_k`/`reranker_top_n`/`reranker_candidates`** — tuned when "the right document" was 1-of-4; a relevance threshold calibrated on four documents means nothing at four hundred, and this is the first thing that breaks when the corpus grows (see the legal-books row below, which grows it deliberately). **`est_chars_per_token=4.89`** — measured on English legal prose from one drafting house; a Ukrainian-language contract, an OCR'd scan, or a table-heavy exhibit tokenizes differently, and this figure propagates into `review_headroom_chars` and every budget comment in `config.py`. **`ollama_num_predict_review=8192`** — "a real review emits ~4.6k tokens of tables" is a statement about *these* contracts; a genuinely long one gets a silently truncated review. **`chunk_min_tokens`/`chunk_max_tokens`** (50/400) and **`_CHARS_PER_QUOTE_LINE=141`** in compaction.py — both fitted to how these documents are written. **`chat_context_max_chars=150000`** is mixed: the derivation is mechanism (a 30s ceiling divided by a measured prefill rate) but the sanity check beside it — "at 150k the full MSA + playbook + a review block all fit" — is pure corpus. **What to do about it:** not to re-tune now, which would only overfit harder, but (1) prefer derived bounds over constants wherever a subtraction is available — the review-path headroom in `llm_caller.py` is the pattern (deleting `msa_max_chars` the same way was tried and reverted, see the MSA-cap row above); (2) make each remaining corpus constant *say* it is corpus-derived in its comment, so the next person knows which numbers to re-measure rather than trust; (3) treat the first non-Trinetix, non-English, or scanned document as a **re-measurement event**, not a normal ingest. |
| **Index the legal reference books for retrieval-augmented checking** | Medium | Raised 2026-08-27. We hold several legal books that are not indexed at all today; RAG covers only client documents in `legal_docs`. Two distinct uses, worth separating because they have different risk profiles. **(a) Attorney-initiated lookup** — "what does the Civil Code say about liquidated damages here?" — is a straightforward retrieval turn and low risk: the attorney asked, and the answer is quoted with a citation. **(b) Agent-initiated augmentation** — the model decides mid-review that a clause needs checking against statute — is the valuable one and the dangerous one, because it puts a *new source of legal authority* into a prompt whose governing rule is that **SKILL.md is the ceiling** and the model must never improvise from pretraining. A book is not the playbook. If a retrieved passage can contradict the firm's position, the precedence has to be explicit and structural (the way `_MSA_COMPARISON_DIRECTIVE` defers all judgment to the playbook), or we have quietly given the model a second authority to reason from. Design notes for when this is picked up: books need their own collection or a `doc_type` that `client_id` filtering cannot accidentally mix with client material (constraint 3 is about tenancy, and a book belongs to no tenant); citations need book + edition + section, not `doc_id`, or the parser's `doc_id:` grep produces nonsense; chunking legal prose at `chunk_max_tokens=400` was tuned on contracts and will cut statutes mid-provision; and this multiplies the corpus by an order of magnitude, which is exactly the condition under which `min_confidence_score=0.45` stops being meaningful (see the row above). Also a real prefill cost — a retrieved statute block competes with the contract for the same budget, so it would need a "trim reference material before the document" rule — none exists today, the MSA's was reverted (see the MSA-cap row above; `_cap_chat_context` truncates only the document). |

When the overflow originates OUTSIDE the document — an attorney pastes a contract into the chat box, so it lands in `system & question` — that `max(0, …)` floors to zero, the entire contract is dropped, **and the prompt is still over budget**, because cutting the document was never going to close a 93k-char question. The compaction gate requires a quote to be a COMPLETE SENTENCE of the row it cites, and a pipe-delimited markdown table row has no sentence terminator followed by a capital — so an 8,355-char table answer (324 pipes) offered **8** quotable boundaries in the entire row and contributed **zero** quotes to its segment.
